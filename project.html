Submission Format Engineering Standards

Submission Requirements & Delivery Format

For each milestone, students submit their work via the course portal. Please refer to the official Project Handout (PDF) and files in the Starter Kit for exact mathematical formulas, baseline requirements, and output schemas:

💻 1. GitHub Repository

A clean, modular private repository containing pinned dependencies in requirements.txt, and a comprehensive README.md detailing environment setup and exact reproduction commands.

📊 2. Output Prediction Files (JSONL)

Prediction files formatted strictly according to predictions_format.md (provided in starter.zip), ready for automated scoring via the official score.py evaluation script.

📄 3. Concise Technical Report (Max 3 Pages PDF)

A concise engineering report covering model selection, comparative metric tables with confidence intervals, baseline evaluations, and qualitative error analysis.

💡 Official Evaluator (score.py):

The official score.py script in starter.zip computes Exact Match (EM), Token F1, and IR retrieval metrics along with 95% bootstrap confidence intervals ($B=1000$):

python score.py <predictions_file.jsonl> --pack course_pack_v1 --split dev

Assessment Protocol Oral Defense

Evaluation Protocol & Oral Defense Structure

📊

Grade Weighting

Approximately 40% of each phase grade is assigned to code correctness, prediction quality, and the written report; 60% is determined by the live oral defense and technical comprehension.

🎙️

Oral Defense Check-In (10–15 Mins)

A 10–15 minute check-in with the phase lead TA: live pipeline execution on 3–5 random queries, inspecting retrieved passages, prompt templates, and testing live parameter adjustments.

💡

Conceptual & Analytical Q&A

In-depth discussion on metric trade-offs, empirical effects of hyperparameters (e.g. $k$, document masking, prompt design), and failure mode diagnosis.

🤝
Academic Integrity & AI Assistance Policy: Brainstorming with peers and utilizing modern AI coding assistants as productivity aids is welcomed; however, every student must personally understand all submitted code and be prepared to explain and modify it live during oral defense.

Course Policies Grace Budget & Bonus

Deadlines, Grace Policy & Software Engineering Bonus

⏳

48-Hour Grace Budget

Each student receives 48 free grace hours across the entire semester to accommodate unexpected delays without penalty.

📉

Late Deduction Rate

Submissions beyond the 48 grace hours incur a 0.5-point deduction per hour (out of 100 for the phase).

🚪

Extended LMS Window

The submission portal remains open for 96 hours (4 days) after the deadline to handle unforeseen technical issues.

🎁

Early Submission Bonus

Submitting early with strong performance (>80%) awards bonus hours (up to 24 hours) back into your semester grace quota.

🏆 Software Engineering & MLOps Extra Credit

Adopting production-grade software engineering practices earns extra credit, evaluated in 1–2 minutes during the oral defense:

Configuration Management: Centralized hyperparameters in structured YAML (e.g., run_config.yaml).
Unit Testing: Automated unit tests with pytest verifying IR metrics and document masking.
Continuous Integration: Automated GitHub Actions running tests on every push.
Experiment Tracking: Tracking metric curves and runs using MLflow or Weights & Biases.
